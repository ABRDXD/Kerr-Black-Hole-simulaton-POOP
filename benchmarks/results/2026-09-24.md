# CPU integrator baseline — 2026-09-24

Measured locally on Windows, AMD Ryzen 7 7445HS, LLVM-MinGW 20260922 / Clang 23.1.2,
CMake 4.4.3, Ninja 1.13.2, Release (`-O3 -DNDEBUG -fno-fast-math -ffp-contract=off`).
Power mode, thermal state, and background OS activity were not controlled. No GPU is used.
Source state: the Milestone 3 implementation in this workspace; it is not yet a Git checkout.

Reproduce from the project root:

```powershell
.\build.ps1 -Configuration Release
.\out\build\windows-clang-release\kerr_benchmark.exe --csv out\cpu-integrators.csv
```

Raw results: [2026-09-24-cpu-integrators.csv](2026-09-24-cpu-integrators.csv).
The recorded run was performed after all build/test processes completed.

Each row is one ray, with one warm-up and seven measured integrations; the median is reported.
These short measurements are descriptive, not stable throughput estimates or percentile latency claims.
The full CSV includes both `rtol=1e-7` and `1e-10` (RK4 instead uses fixed `h=0.1` and `0.025`).
Both adaptive methods use `atol=0.01 rtol`, initial `h=0.02`, and maximum `h=0.5`.

All cases use `M=1`, Cartesian Kerr-Schild coordinates, and future-directed null initial data
constructed from the listed spatial **covariant momenta**:

| Case | Spin | Initial (x,y,z) | Initial (p_x,p_y,p_z) | Final affine parameter |
|---|---:|---|---|---:|
| weak | 0 | (100,1,2) | (-0.8,0.4,0.1) | 12 |
| kerr_strong | 0.8 | (10,1,3) | (-0.8,0.4,-0.1) | 12 |
| near_extremal | 0.999 | (5,1,0.7) | (-0.2,0.8,0.1) | 8 |

The following comparison uses the tighter adaptive tolerance and finer RK4 step:

| Case / method | RHS evaluations | Median ms | Max absolute endpoint error | Max normalized null residual |
|---|---:|---:|---:|---:|
| weak / DOPRI5 | 157 | 0.1117 | 3.29e-14 | 1.34e-16 |
| weak / midpoint8 | 547 | 0.3256 | 1.99e-13 | 1.36e-15 |
| weak / RK4 | 1921 | 1.2399 | 9.24e-14 | 8.85e-16 |
| kerr_strong / DOPRI5 | 349 | 0.2545 | 3.71e-11 | 1.27e-11 |
| kerr_strong / midpoint8 | 547 | 0.3343 | 2.20e-13 | 2.81e-14 |
| kerr_strong / RK4 | 1921 | 1.3165 | 4.00e-11 | 4.80e-12 |
| near_extremal / DOPRI5 | 307 | 0.2231 | 8.86e-11 | 1.21e-11 |
| near_extremal / midpoint8 | 379 | 0.2319 | 4.88e-13 | 1.13e-14 |
| near_extremal / RK4 | 1281 | 0.8476 | 5.78e-11 | 1.54e-12 |

Endpoint error is the maximum absolute component difference over `(t,x,y,z,p_t,p_x,p_y,p_z)`
against an eighth-order run at `rtol=8e-15`. Reference sensitivity compared with `2e-14` was
`3.98e-13`, `3.31e-14`, and `2.16e-14`, respectively. Weak-field differences are roundoff-sized
and do not resolve an accuracy ranking. These are empirical comparisons, not rigorous error bounds.

DOPRI5 is retained for CPU tracing: it has lower derivative work here and already supplies dense
event output. The eighth-order implementation gives tighter strong-field endpoints and serves as
the independent-method reference. Neither adaptive method is unrestricted by the shared maximum
step, so these data do not settle optimal controller settings or a GPU implementation choice.

This benchmark excludes event isolation, file I/O, camera rays, radiative transfer, and rendering.
Separate regression tests cover capture/escape, near-critical rays, and disk events. Those paths
are not yet a comprehensive timing suite. No FPS or RTX 3050 performance claim follows from this report.
