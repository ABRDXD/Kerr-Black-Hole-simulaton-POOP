# Headless Vulkan geometry gate and CPU regression — 2026-10-07

Milestone 5 now has a working headless Vulkan 1.3 compute path. This is pointwise
geometry conformance, not GPU geodesic integration, image validation or an FPS benchmark.

This report preserves the original headless measurements. The later same-day
[Windows presentation continuation](2026-10-07-window.md) records upgraded
development headers/layers, the shared-context regression and partial window gate.

## Hardware and configuration

Windows; AMD Ryzen 7 7445HS; LLVM-MinGW 20260922 / Clang 23.1.2; CMake 4.4.3;
Ninja 1.13.2. Source is this workspace, which has no Git repository/revision.
CPU builds use warnings as errors, no fast-math and `-ffp-contract=off`.

formula/ABI v1. Pins and notices are in THIRD_PARTY.md. The OS loader reports
instance API 1.4.321 (system loader file 1.4.321.1); the application requests 1.3.

## Measurements

723 fixtures: 711 valid points and 12 invalid/schema/degeneracy/overflow cases.
58,302 floating-point reference comparisons per full batch. Valid cases cover
M=1e-6,1,1e6, chi=0,+/-0.8,0.999999,+/-1, both axes, equator, horizon,
interior, negative-q radius branch and weak field, plus 513 deterministic random
points. References evaluate the exact uploaded floats promoted to double.

Separate [NVIDIA](2026-10-07-nvidia-metric-v1.csv) and
[AMD](2026-10-07-amd-metric-v1.csv) per-case CSVs retain each device's measurements.
The two devices have the same reported global maxima, with differing per-case
errors in 493 rows. Bounds were fixed in GPU_PHYSICS.md before the first dispatch.

| Quantity | Max absolute error (mixed fixture scales) | Max error / allowed bound | Failures |
|---|---:|---:|---:|
| r, F, covariant and inverse metric | 292.0065613 | 0.01808700464 | 0 |
| Spatial inverse-metric derivatives | 9.159880519 | 0.03322919824 | 0 |

The raw absolute maxima combine different units/scales: large far-field radii
and derivatives at small M naturally dominate. They are not errors of a typical
M=1 metric component. The dimensionless fractions compare each value with its
own absolute-plus-relative bound and are the acceptance metric.

All matrices/partials are exactly symmetric, all valid payloads finite, all failed
payloads zero and all schema/case/status fields correct. Additional dispatches
of 1,63,64,65 records and the reversed 723-record batch reproduce the full-batch
records exactly. Empty input and excessive application work are rejected on CPU.
Reflection rejects 27 mutated/truncated shader variants covering descriptor sets,
bindings, offsets, strides, scalar types, lengths and workgroup size.

The expanded negative test exposed a real host-budget gap: AMD advertises a
UINT32_MAX group-count limit, so treating that count as universally invalid
submitted an enormous workload and caused device loss. The host now imposes a
16,384-group application ceiling independently of driver limits. Both devices
pass the negative test and complete all final runs after this correction.

Final development captures timed the initial cold full dispatch at 0.04272 ms
(AMD) and 0.257184 ms (NVIDIA). These single timestamps exclude pipeline creation,
host upload/reference/readback and repeated-batch tests; validation was active.
Power, thermal and OS background state were uncontrolled. No throughput, device
ranking or interactive performance claim follows from these values.

## CPU regression and limits

The [CPU CSV](2026-10-07-cpu-integrators.csv) has all 18 rows' work and numerical
columns identical to 2026-09-28. Timing varies; no speedup claim is made. The
benchmark ran separately from build/test processes and still excludes observer
sessions, events and rendering. The original report defines its workloads.

Final Debug, Release and ASan/UBSan builds run the nine CPU suites (95,463 checks)
plus shader-ABI and GPU conformance suites. The GPU CTest requires validation;
both physical devices are additionally checked by the validation helper.

Linux, noncoherent-memory hardware, forced out-of-memory/device-loss recovery,
broader near-ring/exponent coverage, GPU trajectories, swapchain and visible
rendering remain unvalidated. A fence has a 30-second deadline; safe teardown
after a failed submission still depends on the driver's device-idle completion.
The platform code reports a typed API error and does not attempt device recovery.
CLI checks also confirm controlled failures for missing shaders/layers, invalid
device indices and invalid validation modes. The device probe works without a shader.

Reproduce:

```powershell
.\tools\bootstrap-vulkan.ps1 -Validation
.\build.ps1 -Configuration Release -Vulkan -RequireValidation
.\tools\validate-vulkan.ps1 -Device 0 -Csv out\gpu\amd-metric-v1.csv
.\tools\validate-vulkan.ps1 -Device 1 -Csv out\gpu\nvidia-metric-v1.csv
.\build.ps1 -Configuration Debug -Vulkan -RequireValidation
.\build.ps1 -Configuration Sanitize -Vulkan -RequireValidation
```

Device indices are local enumeration indices; use `kerr_gpu --probe` on another
machine. CPU-only builds remain the default, independent of Vulkan headers,
shader compilers, loader, drivers and validation layers.
