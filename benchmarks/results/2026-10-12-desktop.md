# KerrLab desktop implementation and verification record

Recorded: 2026-10-12.

This is a retrospective record of the desktop milestone, combining the prior
conversation's implementation and visual-check results with a read-only source,
artifact, and log inspection. No new build, runtime test, GUI interaction, or
performance benchmark was executed while writing this record. It does not
replace missing earlier web-demo test evidence.

## Delivered implementation

The default Windows launcher now opens a portable Electron application. Its
entry point is `web-demo/desktop/main.cjs`; `tools/package-desktop.cjs` assembles
the application under `out/desktop/KerrLab/`. `KerrLab.exe` loads the bundled
`resources/app/dist/index.html`. The packaged application needs its surrounding
folder, but does not need a separate Node installation, browser tab, or local
HTTP server. Browser preview remains an optional developer path.

The application hosts the imported WebGL 2 renderer and the local KerrLab
presentation layer: four cinematic scenes, reset, fullscreen, cinema view,
PNG capture preview, and visible startup/context-loss errors. The imported
source also contains free-fall, weak-field multi-mass and approximate merger
modes, diagnostic controls, and an optional separate WebGPU still renderer.
Their presence in source is not a claim of complete desktop validation.

Electron is pinned to `44.7.0` in `web-demo/package.json` and the package lock.
The desktop renderer has Node integration disabled, context isolation and
sandboxing enabled, restricted navigation and permissions, and a packaged
content security policy. A native save-dialog handler is configured for PNG
downloads. No C++ physics bridge is present.

## Separate native implementation

The working desktop image is generated by the imported WebGL renderer inside
Electron. It is independent of the C++20 reference physics and Vulkan code.
Passing the native geometry, worldline, observer, session, or GPU conformance
tests does not validate the imported TypeScript, GLSL, or WGSL implementations.

The native GLFW/Vulkan window still presents a diagnostic image rather than
this black-hole renderer. Its existing AMD suspend/restore timeout concern
remains unresolved; see `2026-10-07-window.md`. Launching the Electron window
does not close that compatibility gate.

The user's local-copy instruction does not supply a new upstream license;
this portable package is not a public release.

The imported single-Kerr renderer numerically integrates light paths with
finite precision and finite work budgets. Disk emission prescriptions,
procedural sky and bloom include approximations or artistic choices. The
binary/merger metric is an approximate superposition, not a numerical-
relativity solution. The existing diagnostic and accuracy limits must remain
visible in future scientific claims and roadmap acceptance criteria.
